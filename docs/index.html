一次监测如何形成结论

每一步都保留原始证据和状态。失败、未登录、选择器变化与“没有提及品牌”不会混成同一种结果。

01 · 组合任务

问题 × 平台

锁定品牌版本、提示词和采集模式，生成可重复的运行单元。

02 · 获取回答

API 优先

不可用时按配置回退到浏览器、Webhook 或人工证据。

03 · 规范化

统一证据

标准化回答、URL、域名、搜索词和来源阶段字段。

04 · 语义分析

品牌与竞品

规则保证可复核命中；AI 补充归一、语境、推荐倾向。

05 · 聚合比较

跨维度统计

按平台、提示词、时间和来源计算表现与重复性。

06 · 下一轮实验

策略验证

把弱曝光和来源机会转成新问题或内容建设假设。

平台证据不是理想化漏斗

不同平台公开的信息深度不同，所以各阶段先作为独立观察保存；只有同一来源确实同时观察到上下游阶段时，才计算转化率。

能够直接观测

  • 回答最终输出文本、状态、采集方式与时间。
  • 最终引用页面或 API 明确返回的 URL、标题和引用顺序。
  • 实际搜索词平台明确暴露时记录；没有暴露就保持未知。
  • 阶段轨迹召回、选材、引用分别记录证据级别。

指标使用边界

  • 完整轨迹允许计算来源从召回到选材、引用的同源转化。
  • 仅最终引用可用于引用覆盖和域名频率，不能反推它未被召回。
  • 品牌曝光分母只使用成功回答；失败采集不等于品牌未出现。
  • 竞品覆盖只使用已完成品牌分析的回答，旧数据不自动视为无竞品。
核心原则未知就是未知。BrandScope 不把平台未公开的中间步骤补成 0，也不把竞争品牌曝光比例解释成市场份额。

页面对应的决策问题

每个页面都服务于一类研究判断，汇总层和证据层可以互相追溯。

1

可见性概览

目标品牌是否出现、平均位置如何、哪个平台或问题值得优先处理？

2

AI 交流

当前证据能说明什么、哪些结论仍缺样本、下一步应该验证什么？

3

回答证据

某个汇总指标来自哪一次回答、哪些引用以及什么失败状态？

4

信源研究

哪些网站稳定进入引用，哪些只在特定平台、问题或时间出现？

5

提示词实验

用户意图变化是否显著影响曝光，什么问题更可能引出目标品牌？

6

采集配置

品牌识别、平台通道、登录态、API 和定时任务是否已经准备好？

核心数据模型

运行批次连接问题和平台回答；回答再连接最终引用、搜索词、阶段观察与品牌提及，确保聚合结果可以回到原始记录。

实体职责主要关系不会承载的推断
runs一次提示词任务及触发方式一个运行对应多个平台结果不代表所有平台都成功
results平台回答、状态、品牌命中与位次连接来源和分析明细失败结果不进入曝光分母
sources最终回答明确引用的网址从属于单个结果不等同完整搜索结果集
search_queries平台实际使用或明确返回的搜索词从属于单个结果不凭回答文本猜测搜索词
source_observations来源在召回、选材、引用阶段的观测连接查询、域名和结果不可见阶段保持未知
brand_mentions目标与竞争品牌、顺序、倾向和证据从属于已分析结果曝光比例不等于市场份额
